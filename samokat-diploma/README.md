# Яндекс Самокат

Это рабочая подготовка дипломного проекта по предоставленным требованиям.
Точные условия второй практической части пока не предоставлены: соответствие
автотеста и SQL заданию нужно сверить перед сдачей. Мобильные UI-тесты не выполнены.

## Автотест API

Сценарий: создать новый заказ, сохранить его `track`, получить заказ по `track`,
проверить HTTP 200 и данные заказа. После проверки отменяется только созданный
тестом заказ. Пути и параметры проверены по `/docs/` действующего стенда и
по исходному регрессионному набору.

Данные автотеста явно синтетические: «Ян», «Тестов», «Тестовый адрес 1»
и телефон из одиннадцати нулей. Они не являются данными пользователя.
Действующий адрес стенда вводится через переменную окружения; пароли новых
тестовых курьеров генерируются случайно и сохраняются только локально.

Нужен Python 3.10 или новее. В Windows открой PowerShell в папке проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:SCOOTER_BASE_URL = "https://ID-ТВОЕГО-СТЕНДА.serverhub.praktikum-services.ru"
.\.venv\Scripts\python.exe -m pytest -v
```

Вставь актуальный адрес своего стенда из Практикума вместо примера.
Если стенд изменится, задай новый адрес перед запуском:

```powershell
$env:SCOOTER_BASE_URL = "https://НОВЫЙ-ID.serverhub.praktikum-services.ru"
.\.venv\Scripts\python.exe -m pytest -v
```

Для macOS или Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
export SCOOTER_BASE_URL="https://ID-ТВОЕГО-СТЕНДА.serverhub.praktikum-services.ru"
.venv/bin/python -m pytest -v
```

Структура:

- `configuration.py` — адрес, пути и таймаут.
- `data.py` — валидное тело заказа, дата доставки вычисляется заново.
- `sender_stand_request.py` — создание, получение и отмена заказа.
- `test_order_track.py` — фикстура с подготовкой и уборкой, затем сам тест.
- `requirements.txt`, `pytest.ini`, `.gitignore` — зависимости и настройки.
- `prepare_mobile.py` — отдельный скрипт для создания курьеров и заказов.
- `sql/` — чтение схемы и два предварительных запроса, которые ещё не выполнялись.
- `evidence/` — результат фактического запуска автотеста.

`json=body` передаёт тело JSON и выставляет заголовок `Content-Type`.
`params={"t": track}` передаёт трек-номер в query строки URL.
`assert` сравнивает ответ с ожиданием; при несовпадении тест завершается ошибкой.

## Мобильное приложение

Рабочие копии ретеста, регресса и отчёта подготовлены отдельно в Google Drive.
Ретест содержит 4 исходных бага. Регресс содержит все 10 исходных кейсов.
Их результаты заблокированы до предоставления APK новой версии и прогона на устройстве.

Тестовые данные уже подготовлены на текущем стенде. Учётные данные находятся
в `mobile_environment.json`; этот файл не следует публиковать в GitHub.
Повторный запуск `prepare_mobile.py` создаст новый набор, поэтому он нужен
только после сброса стенда или удаления старых тестовых данных.

Чтобы настроить мобильное приложение, нажми `?` на экране входа, вставь адрес
из своего стенда без `/api` и `/docs`, затем войди вторым курьером.
Перед прогоном укажи версию APK, Android, модель устройства и разрешение экрана.

Для ретеста статус бага `Закрыт` ставится после успешной проверки исправления,
`Переоткрыт` — если исходный дефект воспроизводится. До проверки статус остаётся
`Готов для тестирования`. Не переписывай старый фактический результат баг-репорта:
новый результат вноси в отдельный комментарий с окружением и доказательством.

Для регресса используй `Passed`, `Failed` или `Blocked`. При `Failed` добавь
ссылку на отдельный баг-репорт. `Blocked` в подготовленных таблицах обозначает
отсутствие APK, а не обнаруженный дефект приложения.

Для нотификации нужен отдельный заказ с датой доставки в день проверки;
подготовленные обычные заказы имеют завтрашнюю дату. Дату и время устройства
меняй только для этого кейса, затем верни автоматическую настройку.

## База данных и GitHub

Известна схема `Couriers` и `Orders`. Реальный доступ по SSH из текущего
окружения не установился: hostname `serverhub.praktikum-services.ru`
не разрешился. SQL не выполнялся на учебной БД.

Сначала нужны точные SQL-задания из второй практической части. После их получения
проверь схему через `schema_check.sql`, выполни запросы, сохрани результат и
опубликуй код в предназначенном для диплома репозитории.

Для загрузки через сайт GitHub создай репозиторий, выбери `Add file` →
`Upload files` и загрузи содержимое проекта без `.venv`, `__pycache__`
и `mobile_environment.json`. Если у тебя уже есть дипломный репозиторий,
используй его. В QA-портфолио материалы размещены в отдельной черновой ветке;
SQL-задания и соответствие автотеста условиям диплома ещё нужно подтвердить.
