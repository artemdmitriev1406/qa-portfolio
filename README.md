## Testing approach

1. Clarify the business rule and identify missing acceptance conditions.
2. Prioritize critical user journeys, data integrity, and high-impact regressions.
3. Design positive, negative, boundary, state, and dependency-based scenarios.
4. Collect evidence from the UI, Network, API, logs, database, and environment where applicable.
5. Report defects with reproducible steps, expected and actual results, environment, and impact.
6. Retest fixes and run targeted regression around the affected flow.
7. Summarize residual risk and provide a release recommendation.
